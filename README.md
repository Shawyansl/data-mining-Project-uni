# تحلیل بازار خودرو و املاک

این پروژه دو بازار آگهی را در یک جریان اجرا می‌کند: خودروهای کارکرده از باما و ملک‌های فروش و اجاره از شیپور. هر اجرا آگهی‌های تازه را جمع‌آوری می‌کند، تحلیل پایه و مقایسه‌ی همتاها را انجام می‌دهد، snapshotها را به PostgreSQL اضافه می‌کند و داشبوردهای Grafana را به‌روز می‌کند.

## اجرای یک دور کامل

پیش‌نیاز: Docker و Docker Compose. از ریشه‌ی پروژه اجرا کنید:

```bash
cp .env.example .env
```

در صورت نیاز رمزهای داخل `.env` را عوض کنید. سپس فرمان زیر را اجرا کنید:

```bash
docker compose --profile tools run --rm pipeline --pages 1
```

این فرمان PostgreSQL و Grafana را در صورت نیاز بالا می‌آورد، از هر پنج جست‌وجوی خودرو و هر دو دسته‌ی فروش و اجاره‌ی ملک داده می‌گیرد، هر CSV را با نام یکتای همان دور در `data/` نگه می‌دارد و آگهی‌های دارای داده را تحلیل و به PostgreSQL اضافه می‌کند. Grafana روی [http://localhost:3001](http://localhost:3001) در دسترس است؛ داشبوردهای خودرو و املاک جداگانه در صفحه‌ی Dashboards دیده می‌شوند.

برای گرفتن صفحه‌های بیشتر، مقدار `--pages` را افزایش دهید. برای ارزیابی چندباره، همین فرمان را حدود ده بار در زمان‌های جدا اجرا کنید؛ هر دور CSV جدید می‌سازد و snapshot تازه به تاریخچه اضافه می‌کند. اگر منبعی در یک دور آگهی ندهد، آن بخش از ذخیره‌سازی رد می‌شود و داده‌های قبلی باقی می‌مانند.

برای اجرای سرویس‌ها بدون scraper:

```bash
docker compose up -d db grafana
```

## ساختار پوشه‌ها

- `cars/`: scraper باما، جست‌وجوها، نمونه CSV و تحلیل خودرو.
- `real_estate/`: scraper شیپور و تحلیل ملک.
- `pipeline/`: تصویر Docker و هماهنگ‌کننده‌ی دریافت و ذخیره‌ی هر دو بازار.
- `data/`: CSVهای دورهای اجرا؛ محلی هستند و وارد Git نمی‌شوند.
- `grafana/`: datasourceها و دو داشبورد.
- `reports/<run-id>/`: خلاصه‌های CSV و نمودارهای هر اجرا؛ خروجی هر اجرا جداگانه ذخیره می‌شود تا گزارش‌های قبلی دست‌نخورده بمانند.

## تاریخچه و داده‌های قبلی

اطلاعات هر آگهی در جدول snapshot مربوط به همان بازار با کلید آگهی و زمان استخراج ذخیره می‌شود. اجرای دوباره داده‌ی تازه را اضافه می‌کند و نماهای `car_listings_current` و `real_estate_listings_current` آخرین snapshot هر آگهی را نشان می‌دهند. PostgreSQL فقط داخل شبکه‌ی Docker در دسترس Grafana و pipeline است و پورت میزبان اشغال نمی‌کند. همچنان از volume پایدار `postgres_data` استفاده می‌کند. از `docker compose down -v` استفاده نکنید مگر این‌که عمداً بخواهید تاریخچه‌ی ذخیره‌شده را پاک کنید.

## داشبوردها و تفسیر نتایج

### خودرو

قیمت توافقی، کمتر از ۱۰۰ میلیون تومان و کارکرد غیرواقعی در مقایسه‌ی قیمت وارد نمی‌شوند. برآورد منصفانه میانه‌ی آگهی‌های همان واریانت با اختلاف سال حداکثر یک سال، وضعیت صفر/کارکرده و کارکرد نزدیک است. حداقل دو همتا لازم است؛ نامزد زیرقیمت دست‌کم ۱۵٪ پایین‌تر از baseline است. این baseline توضیح‌پذیر است و مدل ML آموزش‌دیده نیست؛ تعداد نمونه و همتاها را کنار نتیجه ببینید.

### املاک

فروش و اجاره جدا بررسی می‌شوند. فروش بر مبنای قیمت هر متر مربع مقایسه می‌شود؛ ودیعه و اجاره‌ی ماهانه نیز جدا می‌مانند و با نرخ فرضی به یکدیگر تبدیل نمی‌شوند. همتاها از همان نوع ملک، شهر و محله، با اختلاف متراژ حداکثر ۲۵٪ و اتاق مشابه (اگر موجود باشد) انتخاب می‌شوند. حداقل دو همتا برای برآورد لازم است. پرچم غیرعادی از modified z-score قیمت واحد در گروه همتا به‌دست می‌آید و حداقل چهار همتای قیمت‌دار می‌خواهد؛ صفر بودن نامزدها می‌تواند نتیجه‌ی کمبود نمونه باشد. این پرچم فقط برای بازبینی است.

برای هر دو بازار، قیمت‌ها قیمت پیشنهادی آگهی‌اند، نه قیمت قطعی معامله. پوشش استخراج، تعداد همتا و محدودیت نمونه روی کیفیت برآورد اثر می‌گذارد.
